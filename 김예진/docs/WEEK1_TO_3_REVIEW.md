# 데이터 1~3주 차 재검토 결과

## 결론

현재 범위는 데이터 담당 MVP에 적절하다. 1주 차에는 출처와 공통 규격, 2주 차에는 자동 수집·변환·품질검사, 3주 차에는 DB 전달·거리 기준 예비 분석·현장검증 준비까지만 수행한다. 사용자 제보, 실시간 상태 추론, AI 신뢰도 판정은 아직 근거 데이터와 운영 정책이 없어 후속 범위로 남긴다.

## 재검토에서 보완한 사항

- 동일 원본 재실행 때 현재 시각 때문에 파생 파일이 매번 바뀌던 문제를 제거했다.
- GeoJSON의 구식 `crs` 멤버를 제거하고 경도·위도 순서를 자동 검사한다.
- 전달 파일 6개의 SHA-256 체크섬을 생성한다.
- 실제 현장검증 결과 파일을 자동 실행이 덮어쓰지 않도록 분리했다.
- 길이가 다른 경로의 비중을 반영하도록 민감도 분석에 가중 커버리지를 추가했다.
- DB 재적재 때 원본에서 사라진 시설도 제거해 최신 스냅샷과 동기화한다.
- Supabase의 RLS 정책뿐 아니라 `anon`, `authenticated` 읽기 권한도 명시했다.
- 두 공식 출처 중 하나라도 수집·검증에 실패하면 현재 스냅샷을 교체하지 않도록 단계적 갱신과 복구를 적용했다.
- 원본의 빈 주소와 `-` 표기를 추정 문자열이 아닌 `null`로 정규화했다.

## 아직 완료로 처리하지 않는 항목

- 실제 TMAP 경로 좌표를 사용한 민감도 재분석
- 지도 표본 20개와 종류별 현장 표본 3개 이상 확인
- 팀 Supabase 개발 DB에서 마이그레이션·적재·공간함수 실행
- 스마트보안등 위치와 IoT 상태 데이터의 장비 ID·시각 조인 검증

이 네 항목은 외부 키, 현장 방문 또는 백엔드 담당자의 개발 DB가 필요하므로 코드만으로 완료했다고 표시하지 않는다.
