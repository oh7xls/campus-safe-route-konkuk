# 결정 기록

## 001. 파일럿을 건국대·건대입구 반경 1km로 변경

광진구가 공식 CCTV 설치 좌표와 스마트보안등 WGS84 좌표를 모두 제공하고 있어 위치 근거가 분명한 지역으로 옮겼다. 기본 시나리오는 건대입구역 2번 출구에서 건국대학교 건국문까지다.

## 002. 시설은 경로 조회 후 경로 주변만 표시

초기 화면에서 파일럿 전체 시설을 표시하면 정보 과부하와 겹침이 발생한다. 실제 TMAP 경로가 있을 때만 CCTV 70m, 보안등 35m 이내 위치를 표시한다. 이 거리는 MVP의 비교 기준이며 실제 촬영·조명 범위가 아니다.

## 003. 시설 거리는 폴리라인 선분 기준으로 계산

API가 주는 경로 꼭짓점의 밀도에 따라 결과가 달라지지 않도록 점에서 각 선분까지의 최소 거리를 사용한다. 지도 표시와 참고지수의 주변 시설 개수도 같은 함수를 공유한다.

## 004. 보안등 점등·고장 상태는 아직 표시하지 않음

공식 위치 WFS와 갱신된 IoT 측정자료의 식별자·측정시각 결합을 별도로 검증해야 한다. 위치 자료에 없는 최신성을 추정하지 않고 현재는 위치만 쓴다.

## 005. 데이터는 빌드 시점 스냅샷으로 고정

외부 서비스 장애가 시연을 막지 않도록 검증된 정적 스냅샷을 포함한다. 가져오기 스크립트는 좌표·지역·개수 검증에 실패하면 기존 파일을 덮어쓰지 않는다.

## 006. 데모 지도에는 시설과 합성 경로를 그리지 않음

실제 도로를 따르지 않는 선과 시설의 상대 위치가 공식 정보로 오해되는 것을 막기 위해 출발·도착 개념만 표시한다.

## 007. CCTV는 광진구 공식 최신 설치 현황을 우선

전국CCTV표준데이터의 광진구 행은 기준일이 2020-07-08이라 현재 파일럿 근거로는 낡았다. 광진구가 현재 운영 방침 페이지에서 좌표가 포함된 설치 현황을 직접 제공하므로 생활방범·공원방범·어린이보호·다목적 위치를 사용한다. 원본에 없는 실시간 작동 상태나 촬영 방향은 추정하지 않는다.

## 008. 시설 목록은 첫 실제 경로 뒤 지연 로딩

첫 화면에는 시설을 표시하지 않으므로 전체 좌표를 미리 전송할 이유가 없다. 실제 TMAP 경로가 준비된 뒤 그 좌표를 시설 API에 전달하고, 서버가 경로 주변 위치만 반환한다. 경로가 바뀌면 새 경로 기준으로 다시 요청하며 오래된 요청은 취소한다. 전체 시설 목록과 상세 좌표에 중복되는 커버리지 전용 배열은 브라우저로 보내지 않는다.

## 009. 참고지수 표본은 진행 방향과 무관하게 균등 분배

출발점부터 고정 20m 간격으로만 표본을 찍으면 같은 선을 반대로 이동할 때 표본 위치가 달라져 점수가 달라질 수 있다. 전체 길이를 기준으로 구간 수를 정하고 양 끝점을 포함해 표본을 균등 분배한다. 같은 경로 형상을 뒤집은 경우 참고지수가 동일해야 한다.

## 010. 확정 장소의 화면 갱신은 검색 요청으로 취급하지 않음

빠른 선택이나 출발·도착 교환으로 장소가 확정된 경우 검색 제안을 다시 요청할 필요가 없다. 사용자가 입력란을 직접 편집했을 때만 장소 검색을 실행해 불필요한 로딩 표시와 외부 API 호출을 막는다.
